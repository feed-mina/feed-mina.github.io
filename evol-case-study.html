가이드롤 생산 모니터링 시스템
제조 지표 정의 재합의와 불변식 검증

가동 시간과 가동 횟수가 서로 모순되게 표시되던 통계 화면의 원인을 추적해, 코드 버그가 아닌 지표 정의의 불일치임을 밝혔습니다. 현장과 정의를 다시 합의하고, 불변식 검증과 계약 테스트로 고정했습니다. 같은 기간에 첫 화면 조회 속도도 95% 단축했습니다.

시스템 개요

가이드롤은 광학필름 생산 라인에서 동력 없이 필름 장력으로 도는 롤입니다. 롤에 붙은 센서 노드 4대(펄스=속도, 가속도=진동)가 10분마다 11초씩 측정하고, 이 측정 1회분을 사이클이라고 부릅니다. 속도 단위는 분당 이동 거리(MPM, m/min)입니다.

이 시스템은 사이클을 모아 일간 관제(하루 속도 그래프·상태 타임라인)와 기간 통계(주·월 단위 가동 시간·가동 횟수)로 보여 주는 FastAPI · React 대시보드입니다.

문제 정의 및 원인 분석 Problem & Root Cause

단계를 누르면 내용이 바뀝니다

통계 지표 간 모순: 가동 1.2시간 · 가동 0회

한 주 통계 카드에 가동 1.2시간과 가동 0회가 같이 떴습니다. 주별 합 3.7+1.2도 전체 4.8과 어긋나 있었습니다. 개발 단계의 샘플 데이터에서는 재현되지 않던 조합이었습니다.

개발 데이터
  • 노드 4대가 동시에 가동·정지
  • 짧은 가동 구간 없음
  • 횟수와 시간이 항상 같은 방향으로 변화
현장 데이터
  • 전체 사이클의 67%가 정지 상태
  • 한 노드만 움직이는 구간 존재
  • 10분 단위의 짧은 가동이 빈번

원인: 두 지표가 서로 다른 판정 기준을 사용

가동 횟수는 "30분 넘게 이어진 덩어리"만 셌고, 가동 시간은 길이와 상관없이 다 더했습니다. 해당 일에는 10~20분 길이의 가동이 여섯 번 있었고, 이 구간들이 횟수에서는 모두 빠지고 시간에는 모두 합산되었습니다.

횟수(옛) = 30분 이상 덩어리만 센다 → 0회
시간(옛) = 길이 상관없이 다 더한다 → 10분 × 6 = 1.2h
같은 데이터, 다른 문턱

해결: 가동 정의 재합의와 합산 함수 단일화

현장과 함께 "가동 1회"의 정의부터 다시 합의했습니다. 합산 함수 한 곳을 바꾸고, 일간 카드·주별·월별 화면이 모두 그 함수를 쓰게 했습니다.

덩어리 = 1회
속도가 이어지는 구간 하나가 가동 1회
정지→속도 +1
횟수는 이 순간에만 는다
30분 조건 없음
10분 덩어리도 1회
시간 = 같은 덩어리
그래서 0회면 0시간
+상태 전이 4조건 그림정지·속도 두 상태 사이의 네 가지 전이

검증: 불변식 정의 후 36일치 화면 전수 대조

"올바른 화면이라면 반드시 성립해야 하는 조건"(불변식)을 먼저 문장으로 정의하고, 36일치 화면 전부와 대조했습니다.

불변식
  • 0회면 0시간 — 36일 전부 통과
  • 주별 합 = 전체 — 6주 전부 통과
  • 노드 카드 144칸 = 로컬 계산
숫자
  • 옛 규칙: 37일 중 5일에서 모순
  • 새 규칙: 0일
  • 계약 테스트 26건이 규칙을 고정
  • 검증 범위 외: 원파형 상세·비교 탭은 해당 회차에서 미검증

성과: 세 화면의 지표 일치와 조회 성능 개선

일간 카드·주별·월별 화면이 같은 합산 함수를 사용하게 되어 세 화면의 지표가 일치합니다. 함께 첫 조회 지연(게이트웨이 30초 제한으로 인한 502 오류)도 해소했습니다.

지표
  • 가동 1.2h · 6회 (7/6)
  • 세 화면이 같은 덩어리를 센다
  • 결정은 결정대장에 날짜·근거와 함께 기록

현상 — 롤러가 정지해 있어도 필름의 미세 진동으로 센서가 속도를 기록해, 정지 구간의 평균 속도가 0보다 크게 계산됩니다. 1차 사례가 "정의가 서로 달랐던" 문제라면, 이 현상은 정지 판정 기준 자체가 정의되지 않은 문제입니다.

가설과 검증 — 사이클 1회의 측정 칸 220개 중 속도가 기록된 칸의 비율로 실제 가동과 유령 속도를 구분할 수 있다는 가설을 세우고, 실측 682 사이클에서 구분 가능함을 확인했습니다.
