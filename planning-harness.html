Planning Harness.
기획에서 개발 핸드오프까지 연결하는 AI 운영 루프

기획자가 명령어 한 줄로 요구사항 분해, 사용자 플로우, 시퀀스 다이어그램, 테스트 케이스, 릴리즈 노트, GitHub Issue/Project 동기화, 개발 repo 핸드오프까지 진행할 수 있도록 만든 규칙·가드레일 기반 Claude Code 플러그인입니다.

Live Tool ↗ GitHub ↗

What it solves

일회성 프롬프트로 산출물을 만드는 방식은 결과가 흔들리고, 승인 없이 개발 이슈로 넘어가면 추적과 책임 소재가 약해집니다. Planning Harness는 모든 산출물을 SSOT, 즉 Single Source of Truth인 spec.md 기준으로 만들고, 위험 작업은 사람 승인 뒤에만 GitHub로 반영합니다.

SSOT Approval Gate GitHub Sync Dev Handoff

My role

  • 8개 Slash Command 기반 기획 자동화 플로우 설계
  • 사람 승인 게이트를 넣어 AI가 임의로 외부 시스템에 쓰지 못하게 제어
  • 회의록, 요구사항, Mermaid 다이어그램, 테스트 케이스, 릴리즈 노트 산출물 구조화
  • GitHub Issues, Projects, 개발 repo 핸드오프까지 이어지는 운영 파이프라인 설계

8 Skills

  • /search-documents — 근거 자료 검색
  • /split-requirements — 요구사항 분해와 의존성 정리
  • /sequence-diagram — Mermaid 시퀀스 다이어그램 생성
  • /user-flow — 사용자 플로우 시각화
  • /logic-check — 정상/예외/보안/성능 테스트 케이스 생성
  • /release-note — 변경사항 요약
  • /git-project-sync — 회의록 할 일을 GitHub Issue/Project로 동기화
  • /dev-handoff — 승인된 기획을 개발 repo로 전달

Pipeline

spec.md SSOT
→ /split-requirements
→ /user-flow + /sequence-diagram
→ /logic-check
→ 사람 승인
→ /git-project-sync
→ /dev-handoff
→ 개발 Issue + @claude PR trigger

Architecture point

핵심은 AI에게 모든 권한을 주는 것이 아니라, AI가 잘하는 문서화·분해·검증을 자동화하고 외부 반영은 사람 승인 뒤에만 실행하게 만든 점입니다. 그래서 기획 산출물의 속도와 운영 안정성을 함께 잡았습니다.
